## 🎯 Summary

The i18n tooling used a regular expression to discover `__("...")` translation keys, which silently mis-parsed real source code: implicit string concatenation (`__("a " "b")`) and multi-line literals were truncated to their first fragment, kwargs could confuse the match, and 21 legitimate keys were reported as missing while their full forms appeared as false orphans. This change replaces the regex with a real AST-based extractor so the scanner sees exactly the string the runtime lookup builds, and consolidates the previously duplicated extraction logic in the test suite onto that single implementation.

## 🛠️ Technical Changes

- Replace `PATTERN`-based regex scanning in `tests/sync_i18n.py` with an `ast.parse` walk that collects `__()` calls whose first argument is a string `Constant`.
- Correctly fold implicit concatenation and multi-line literals into the single combined runtime key, and ignore `__()` calls with kwargs or non-literal first arguments.
- Add a `SyntaxError` guard so unparsable source files are skipped instead of aborting the scan.
- Use `pathlib` throughout (`Path.read_text`, `rglob`, `is_file`/`is_dir`, `exists`) in place of `os.walk`/`os.path` calls.
- Resolve all paths (source dirs, `langs` directory) relative to the repository root rather than the current working directory, making the script CWD-independent.
- Remove the duplicated AST implementation from `tests/test_i18n.py`; `_extract_keys_ast` now delegates to the shared extractor.
- Rename `TestPatternExtraction` to `TestAstExtraction` and update assertions: adjacent and multi-line literals now yield the joined string (`"a b"`, `"first line second line"`) instead of only the first fragment.

## ⚠️ Impact/Warnings

- Behavior change: extraction now returns the full concatenated key instead of the first literal fragment. Any previously reported "missing key" or "orphan key" output generated by the old regex should be considered stale and regenerated.
- No database, environment variable, or dependency changes; only Python standard library modules (`ast`, `json`, `pathlib`) are used.
- Files containing syntax errors are now skipped silently during scanning — malformed sources will no longer contribute keys and will not raise errors.
- Tooling-only change affecting the i18n consistency test suite; runtime translation behavior is unchanged.
