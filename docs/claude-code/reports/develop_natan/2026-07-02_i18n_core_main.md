## Relatório de Conclusão — Internacionalização (i18n) de core.py e main.py

### O que foi feito
- Aplicado mapa de substituição de `docs/plans/substituir_corepy.md`: todas as strings de UI em `src/core.py` convertidas para inglês com wrapper `__()` para internacionalização
- Aplicado mapa de substituição de `docs/plans/substituir_mainpy.md`: todas as strings de UI em `src/main.py` convertidas para inglês com wrapper `__()`
- Corrigidas 10 chaves duplicadas no arquivo de tradução `langs/pt_br.json`
- Verificado JSON válido com 137 chaves únicas após correção

### Arquivos alterados

| Arquivo | Tipo de mudança | Descrição |
|---|---|---|
| `src/core.py` | feat (i18n) | 41 chamadas `__()` aplicadas: get_git_diff, get_skill_context, generate_pr_content, generate_skill_template, get_base_branch, get_git_full_diff, install_git_hooks, get_branch_history_text |
| `src/main.py` | feat (i18n) | 90 chamadas `__()` aplicadas: banner, contextual help, linter, update, hooks, blame, issue, input, flow, commit, review, PR |
| `langs/pt_br.json` | fix | Removidas 10 chaves duplicadas; JSON válido com 137 chaves únicas |

### Impacto
- **Funcionalidade:** Toda a interface do GitPR agora usa `__()` para strings, permitindo tradução dinâmica via `CURRENT_LANG`. Com `pt_BR`, os textos aparecem em português; com qualquer outra língua, em inglês
- **Performance:** Sem impacto — `__()` é uma chamada de função leve com lookup em dicionário
- **Compatibilidade:** Nenhuma quebra. O fallback do `__()` retorna a chave original se a tradução não for encontrada
