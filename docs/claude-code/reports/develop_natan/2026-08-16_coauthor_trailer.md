## Completion Report — Co-Author Trailer in Generated Commit Messages

### What was done
- Added the trailer `Co-Authored-By: Gitpr-cli <gitpr@natanfiuza.dev.br>` to every commit message generated by gitpr, mirroring the Claude Code co-author pattern.
- Added a read-only opt-out env variable `GITPR_COAUTHOR` (`false` disables the trailer; default is enabled). It is **never** auto-written to `.env` and intentionally undocumented in user-facing docs.
- The trailer is appended programmatically at consumption time (never via the AI prompt, never in the MD5 cache), separated by extra blank lines so it does not appear in GitHub's collapsed commit previews at first glance.
- Helper is idempotent: does not duplicate an existing trailer and preserves third-party `Co-Authored-By:` lines.

### Impact
- **Functionality:** All flows that produce a commit message now carry the co-author signature: `gitpr -c`, `prepare-commit-msg` hook, auto-commit, PR publication TUI, and MCP tool.
- **Performance:** No impact — cache behavior unchanged (the append happens after cache read, so existing cached responses remain valid).
- **Compatibility:** `generate_commit_message` MCP tool output changed (message now includes the trailer); external consumers doing exact-match comparisons need to account for it. The PR description "Recommended Commit Message" block intentionally keeps the pure AI phrase.
