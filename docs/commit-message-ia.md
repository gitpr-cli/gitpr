# Technical Documentation: AI Commit Message Generation (--commit)

The GitPR `--commit` (`-c`) command automatically generates commit messages in the **Conventional Commits** format using artificial intelligence to analyze your local changes and provides a complete interactive TUI workflow to select files, review the message, and execute the commit.

---

## 1. Interactive Commit Workflow

```bash
gitpr -c
```

When run in an interactive terminal, GitPR guides you through a 4-step workflow:

1. **Stage Selector ("Files outside stage")**:
   - If there are unstaged or untracked files, GitPR opens the `StageFilesScreen` modal with checkboxes.
   - You can selectively choose which files to stage (`git add`).
   - Use **"Select All"**, **"Deselect All"**, **"Stage Selected"**, **"Skip Staging"**, or **"Cancel"**.
   - If all changes are already staged, this selector is automatically skipped.

2. **AI Commit Message Generation**:
   - Analyzes the staged diff (`git diff --cached`) using smart path exclusions (`SMART_EXCLUDES`).
   - Generates the Conventional Commit message in a background thread while displaying an animated status modal (`CommitProgressScreen`).

3. **Message Review & Edit**:
   - Displays the generated message in the `CommitMessageScreen` modal.
   - You can review and edit the text directly before confirming.
   - Click **"Confirm"** to proceed or **"Cancel"** to abort without committing.

4. **Animated Commit Execution**:
   - Once confirmed, displays `CommitProgressScreen` with an animated sliding gradient bar.
   - Executes the commit (`git commit -m "..."`) with the co-author signature trailer.
   - Displays real-time logs and the commit SHA upon completion, with a **"Close"** button to dismiss.

---

## 2. Conventional Commits Format

The AI is instructed to generate messages following the standard:

```
type: short description

Optional body with additional details
```

**Types used:** `feat`, `fix`, `refactor`, `test`, `chore`, `docs`

---

## 3. Git Hooks Integration (Non-Interactive)

`--commit` is used internally by the `prepare-commit-msg` hook. When installed via `gitpr -ih`, the hook runs:

```bash
gitpr --commit --hook <temporary-file-path>
```

The `--hook` flag keeps the execution strictly non-interactive: no TUI or modals are opened, and the suggested message is injected directly into the Git editor.

---

## 4. Staging Configuration & Automation

You can customize the staging behavior via environment variables in `~/.gitpr/.env`:

- `GITPR_AUTO_STAGE=true`: Automatically stages all unstaged files without prompting.
- `GITPR_SKIP_UNSTAGED_CHECK=true`: Skips checking for unstaged files.
- `--no-unstaged-check`: CLI flag to skip unstaged files verification for a single run.

---

## 5. Customization via Skill

The AI behavior can be customized through the `.gitpr.commit.md` file inside `.gitpr/skill/`:

```bash
gitpr -s          # Downloads the .gitpr.commit.md template
# Edit the file according to your team's conventions
gitpr -c          # The AI will use your customized rules
```

---

## 6. AI Provider Selection

```bash
gitpr -c -p gemini       # Force Google Gemini
gitpr -c -p deepseek     # Force DeepSeek
gitpr -c -p ollama       # Force local Ollama
```

---

## 7. Response Cache

GitPR generates an MD5 hash of your staged diff + instructions. If you run `gitpr -c` again **without changing the staged code**, the response is returned instantly from the local cache, saving API quotas.

---

## 8. Co-Author Signature

Every commit message generated by GitPR automatically carries the co-author trailer:

```text
Co-Authored-By: Gitpr-cli <gitpr@natanfiuza.dev.br>
```

The trailer is appended programmatically (never by the AI) across all flows: interactive commit TUI, `prepare-commit-msg` hook, PR publication auto-commit, and the MCP `generate_commit_message` tool. It is separated from the message by extra blank lines so it does not appear in GitHub's collapsed commit previews at first glance, and it is never duplicated when the message already contains it.
