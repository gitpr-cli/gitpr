# 📂 Git Status — Uncommitted File Listing & Unstaged Verification

GitPR can list uncommitted file changes without AI processing, and automatically verifies unstaged files before running any AI command (commit, review, full review, issue, and PR).

---

## 1. `--status` Flag — Fast File Listing (No AI)

The `--status` flag lists all uncommitted file changes categorized by type — **no AI, no network, no git fetch**. It runs instantly.

```bash
gitpr --status
```

Example output:
```
📂 Uncommitted changes (no AI):
  ➕ New files (2):
    - src/new_module.py
    - tests/test_new_module.py
  ✏️ Modified files (3):
    - src/core.py
    - src/main.py
    - README.md
  🗑️ Deleted files (1):
    - old_deprecated.py
```

### Categories

| Category | Git status codes | Description |
|----------|-----------------|-------------|
| **New** (`➕`) | `??` | Untracked files — never added to Git |
| **Modified** (`✏️`) | ` M`, `MM`, `AM`, `RM` | Unstaged modifications in the working tree |
| **Deleted** (`🗑️`) | ` D`, `MD`, `AD`, `RD` | Unstaged deletions in the working tree |

> **Note:** Files that are staged (added via `git add`) but have a clean working tree (`M `, `A `, `D `) are **not** shown. The `--status` flag shows only files with **working-tree changes not yet in the staging area**.

## 2. Unstaged File Verification (All Commands)

Before generating any AI analysis, GitPR now checks for unstaged files on **all** main commands:

| Command | Behavior when unstaged files are found |
|---------|----------------------------------------|
| `gitpr` (PR default) | **Interactive** — opens TUI modal to stage, skip, or cancel |
| `gitpr -c` (commit) | **Warning** — alerts that unstaged files will NOT be in the commit |
| `gitpr -r` (review) | **Informational** — notes that unstaged files are still included in the diff |
| `gitpr -f` (fullreview) | **Informational** — notes that unstaged files are still included in the diff |
| `gitpr -is` (issue, diff mode) | **Informational** — notes that unstaged files are still included in the diff |

### Commit-specific behavior

When running `gitpr -c`, the warning is stronger because unstaged files will **not** be included in the commit message generated by the AI:

```
⚠️ 3 file(s) are not staged and will NOT be included in the commit.
  ✏️ Modified files (2):
    - src/core.py
    - src/config.py
  ➕ New files (1):
    - src/new_feature.py
💡 Tip: Use 'git add <file>' to stage them, or pass --no-unstaged-check to skip this verification.
```

If `GITPR_AUTO_STAGE=true` is set, `-c` will auto-stage files before generating the commit message (same as the PR behavior).

### Review/FullReview/Issue behavior

For `-r`, `-f`, and `-is`, the diff already includes unstaged changes, so the analysis is accurate. The message is informational only:

```
ℹ️ 2 file(s) are not staged. They will still be included in this analysis.
  ✏️ Modified files (2):
    - src/core.py
    - src/main.py
💡 Tip: Use 'git add <file>' to stage them, or pass --no-unstaged-check to skip this verification.
```

> **Note:** `GITPR_AUTO_STAGE` is **not** honored for review/fullreview/issue — auto-staging as a side effect of a read-only analysis command would be unexpected.

---

## 3. `--no-unstaged-check` Flag

Skip the unstaged verification for a single invocation:

```bash
gitpr -c --no-unstaged-check
```

This is equivalent to setting `GITPR_SKIP_UNSTAGED_CHECK=true` but only for that one command.

---

## 4. Hook Mode Protection

When GitPR runs inside a Git hook (`--hook` flag, used by `prepare-commit-msg`), the unstaged check is **completely skipped** — any prompt or TUI would hang the `git commit` process.

---

## 5. Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `GITPR_SKIP_UNSTAGED_CHECK` | `false` | Set to `true` to skip the unstaged files check for all commands |
| `GITPR_AUTO_STAGE` | `false` | Set to `true` to automatically stage all unstaged files (PR and commit only) |

## 6. MCP Tools

Two new MCP tools are available for IDE integration:

### `list_unstaged_files`
Returns structured JSON with three categorized lists:
```json
{
  "status": "changes_found",
  "new": ["untracked.py"],
  "modified": ["edited.py"],
  "deleted": ["removed.py"],
  "total": 3,
  "message": ""
}
```

### `analyze_unstaged_diff`
Returns only the **unstaged** diff (index vs working tree), excluding staged changes:
```json
{
  "status": "changes_found",
  "diff": "diff --git a/x.py b/x.py\n-old\n+new"
}
```

> **Note:** Untracked files never appear in git diffs. Use `list_unstaged_files` to see them.

The existing `analyze_diff` tool has been clarified: it returns the **uncommitted** diff (`git diff HEAD` — includes both staged and unstaged changes, but not untracked files).
