# Technical Documentation: Terminal Graphical Interface (TUI) — Issues

This documentation describes the operation of GitPR's interactive graphical interface (TUI) for Issue generation and management, built with the Python `textual` library.

---

## 1. What is the Issues TUI?

When you run the `gitpr --issue` (or `-is`) command, GitPR analyzes your code and opens an interactive panel directly in the terminal. This allows you to review, edit, and enhance the issue generated by the Artificial Intelligence before saving it or sending it to the remote repository.

---

## 2. Context Engines (3 Generation Modes)

The Issues functionality has **3 distinct context engines**, triggered according to the flags combined with `--issue`. Each engine feeds the AI with a different set of information, suited to the development cycle moment.

### 2.1 New Code Issue — `gitpr -is`

**Context:** Current `git diff` (uncommitted changes).

```bash
gitpr -is
```

| Characteristic | Description |
|---|---|
| **Data source** | Local diff (`git diff HEAD`) |
| **When to use** | Before committing — you just finished coding and want to document the task |
| **Result** | Issue describing exactly what is in your working tree |
| **Ideal for** | Quick documentation of recently implemented features, fixes, and refactorings |

> **Tip:** This is the fastest mode. The AI reads only the lines you changed and generates a focused and objective issue.

---

### 2.2 Epic / Release Issue — `gitpr -is -ht`

**Context:** Full history of the current branch (Git Log + Previous PR Cache).

```bash
gitpr -is -ht
```

| Characteristic | Description |
|---|---|
| **Data source** | `git log` of the branch + local cache of PRs generated by GitPR |
| **When to use** | At the end of a feature branch with multiple commits or when closing a release |
| **Result** | Consolidated issue with the complete overview of everything that was developed |
| **Ideal for** | Epics, releases, large features that took several days/commits to complete |

> **Tip:** GitPR scans the exclusive commit history of your branch and the PR reports already generated to build a high-level view. If there are no exclusive commits or previous PRs, the command will display a warning and abort.

---

### 2.3 Archaeological / Technical Debt Issue — `gitpr -is -b file:lines`

**Context:** Timeline of a specific code block via `git blame`.

```bash
gitpr -is -b src/core.py:140-195
```

| Characteristic | Description |
|---|---|
| **Data source** | `git blame` (line-by-line change history) + parent commit tracing (up to 4 levels) |
| **When to use** | When identifying legacy code that needs refactoring or documenting technical debt |
| **Result** | Issue containing the block's chronology: when it appeared, who changed it, how it evolved, and why it needs to be refactored |
| **Ideal for** | Documenting technical debt, justifying refactorings, understanding the evolution of critical code |

> **Tip:** You can also use the interactive format: `gitpr -is -b file` (without specifying lines). GitPR will ask which lines to investigate.

## 3. Issue Structure (What / Why / Where / How)

The GitPR AI is instructed to generate the issue draft following a rigorous software engineering standard to facilitate team communication:

| Section | Description |
|---|---|
| **What** | Direct checklists about the created features or identified problems |
| **Why** | The context and technical motivation behind the implementation |
| **Where** | Specification of affected routes, modules, pages, or resources |
| **How** | Technical breakdown divided into Backend/Engine, Database/Data, and Frontend/CLI/Interface |

> **Customization:** You can customize the template used by the AI through the `.gitpr.issue.md` file at the project root (download with `gitpr -s`).

---

## 4. TUI Shortcuts and Navigation

The interface was designed to be fast and not require constant mouse use. You can navigate through fields using the `Tab` key and use the following shortcuts:

| Key | Action | Description |
|---|---|---|
| **`F1`** | Help | Opens a floating modal with quick interface usage instructions |
| **`F2`** | Save Local `.md` | Exports the screen content to a Markdown file in the current project folder. Ideal when you just want the draft to refine later |
| **`F3`** | Create on GitHub | Connects to the GitHub REST API and automatically creates the issue in the remote repository. The direct link to the newly created issue will be displayed in the terminal |
| **`F4`** | Help (alternative) | Alternative shortcut to open the TUI instructions |
| **`Esc`** | Exit | Aborts the operation and closes the interface without saving any changes |
| **`Tab`** | Navigate | Toggles focus between the issue title and body fields |

## 5. GitHub Integration (PAT Token)

To create issues directly in the remote repository (`F3`), GitPR needs a **Personal Access Token (PAT)** from GitHub with `repo` scope.

### 5.1 Token Configuration

The first time you use `F3`, GitPR will:

1. Detect that no token is configured
2. Display the token generation URL with pre-filled parameters (`repo` scope)
3. Ask you to paste the generated token
4. Store it encrypted (Fernet) in the `~/.gitpr/.env` file

### 5.2 Security

- The token is stored as an encrypted hash — never in plain text
- The master decryption key is located at `~/.gitpr/secret.key`
- See the complete guide at [github-pat-integration.md](github-pat-integration.md)

## 6. Practical Examples

### Example 1: Document a feature before committing

```bash
# You just implemented a login system
gitpr -is
# → The AI reads the diff, generates the draft, and opens the TUI
# → Review, adjust the text if needed
# → Press F3 to create the issue on GitHub
```

### Example 2: Generate a release issue

```bash
# Your feature/payment branch has 15 commits over 3 days
git checkout feature/payment
gitpr -is -ht
# → The AI consolidates all history into an epic issue
```

### Example 3: Document technical debt

```bash
# You found a confusing code block in the legacy file
gitpr -is -b src/legacy/parser.py:200-350
# → The AI traces the block's evolution from the original commit
# → Generates an issue explaining the technical debt and suggesting refactoring
```
